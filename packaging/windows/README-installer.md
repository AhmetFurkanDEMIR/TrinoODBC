# Windows x64 installer (NSIS), built on macOS or Linux

`installer.nsi` is an [NSIS 3](https://nsis.sourceforge.io/) script for a Windows x64 installer
of the Trino ODBC Driver. `build_installer.sh` compiles it with `makensis`, and it runs on macOS or
Linux, so no Windows machine is needed to produce the installer. The result is

```
dist/windows/TrinoODBC-<version>-windows-x64-setup.exe
```

`installer.iss` (Inno Setup, compiled on Windows by `build.ps1 -Installer`) is still used for the
MSVC/vcpkg build. Both installers write the same ODBC registration. See
[Differences from installer.iss](#differences-from-installeriss).

> **Status.** The script compiles cleanly with makensis 3.13 on macOS (`-WX`: no warnings). 7-Zip
> can open and list the installers it produces. The maintainer has installed
> `TrinoODBC-1.0.0-windows-x64-setup.exe` on Windows x64 and used the driver it registers: the
> Windows driver manager loads it, DSNs and connection strings connect, queries run, and Power BI
> Desktop reads through it. After changing the script, go through
> [Checking it on Windows](#checking-it-on-windows) again before you distribute the result.

## Building

Requirements (macOS: `brew install makensis sevenzip mingw-w64`; Debian/Ubuntu:
`apt install nsis p7zip-full mingw-w64`):

* `makensis` 3.x (required),
* `x86_64-w64-mingw32-objdump` or `llvm-objdump` for the DLL import check (optional; without
  one the check is skipped with a warning),
* `7z` / `7zz` / `7za` to list the result (optional).

First produce the stage tree, normally with `packaging/windows/cross_build_mingw.sh`:

```
<stage>/x64/trinoodbc.dll        the driver, plus any non-system DLL it imports
<stage>/docs/*.md                documentation
<stage>/VERSION                  version (first line)
<stage>/powerbi/TrinoODBC.mez    Power BI custom connector
<stage>/powerbi/README.md        optional
<stage>/LICENSE                  optional; turns on the license page
<stage>/assets/                  installer branding (trinoodbc.ico, installer-*.bmp); copied from
                                 packaging/assets/generated by cross_build_mingw.sh
```

Then build the installer:

```sh
packaging/windows/build_installer.sh                 # stage dist/windows/stage -> dist/windows/
packaging/windows/build_installer.sh --stage DIR --out DIR --version 1.2.0
```

| Option | Default | Meaning |
|---|---|---|
| `--stage DIR` | `dist/windows/stage` | stage tree |
| `--out DIR` | `dist/windows` | output directory (created if needed) |
| `--assets DIR` | `packaging/assets/generated`, else `<stage>/assets` | branding: `trinoodbc.ico`, `installer-welcome.bmp`, `installer-header.bmp` (see [Branding](#branding)) |
| `--version V` | `<stage>/VERSION`, else `project()` in `CMakeLists.txt` | `1.2.3` or `1.2.3-rc1`; the version resource gets `1.2.3.0` |
| `--makensis PATH` | `$MAKENSIS`, `makensis` on `PATH`, Homebrew's | NSIS compiler |
| `--no-powerbi` | | leave out the Power BI component (no `powerbi/` needed) |
| `--no-dep-check` | | skip the DLL import check |
| `--no-werror` | | do not treat makensis warnings as errors |

The script works under macOS `/bin/bash` 3.2 and under zsh. Each step is printed, and the script
stops with an error message at the first problem. In order, it:

1. validates the stage. `trinoodbc.dll` must be a PE32+ x86-64 DLL (read from the PE header),
   there must be at least one `docs/*.md`, and `TrinoODBC.mez` must be a ZIP archive,
2. checks the DLL imports. Every DLL that a staged DLL imports must be a Windows system DLL or be
   staged in `x64/`. A static mingw build imports only system DLLs. A dynamically linked one also
   needs e.g. `libstdc++-6.dll`, `libwinpthread-1.dll` or `libcurl-4.dll` next to the driver.
   Every other `*.dll` in `x64/` is installed next to `trinoodbc.dll` and removed by the
   uninstaller,
3. finds the branding folder (`--assets`, else `packaging/assets/generated`, else
   `<stage>/assets`) and checks that `trinoodbc.ico` is an icon file and that the bitmaps are BMPs
   of the size NSIS expects (164x314, 150x57),
4. works out the version and looks for a license file (`<stage>/LICENSE[.txt|.md]`, then the
   repository root),
5. deletes an existing installer of the same name and runs
   `makensis -WX -V2 -INPUTCHARSET UTF8 -DVERSION=… -DVERSION_NUMERIC=… -DSTAGE=… -DOUT=… -DASSETS=…`,
6. prints the installer path, size and SHA-256, and lists the contents with `7z l`. It fails if
   `trinoodbc.dll`, `trinoodbc.ico` (or `TrinoODBC.mez`) is missing from the list.

Re-running the script is safe. With unchanged inputs it produces a byte-identical installer.

**macOS locale.** makensis 3.13 from Homebrew aborts with `std::bad_alloc` ("Generating language
tables") when the locale is `C`/POSIX, which is the default in non-interactive shells. When the
current charmap is not UTF-8, the script sets `LC_ALL` to `C.UTF-8` or `en_US.UTF-8` for makensis.
If you run makensis by hand, do the same:

```sh
LC_ALL=C.UTF-8 makensis -DVERSION=1.0.0 -DSTAGE=$PWD/dist/windows/stage -DOUT=$PWD/dist/windows \
    packaging/windows/installer.nsi
```

(Without `-DEXTRA_DLLS_NSH` only `trinoodbc.dll` is taken from `x64/`, and makensis prints a warning
about it. Without `-DASSETS` the script takes the branding from `<stage>/assets`, else from
`packaging/assets/generated`, and stops with an error when neither has it.)

### Branding

The installer uses the Trino logo, rendered from `packaging/assets/trino-logo.svg` by
`packaging/assets/make_icons.sh` into `packaging/assets/generated/`:

| File | Used as |
|---|---|
| `trinoodbc.ico` (16, 32, 48, 64, 128, 256 px) | setup `.exe` and `uninstall.exe` icon (`MUI_ICON`, `MUI_UNICON`); installed as `<install dir>\trinoodbc.ico` for the Add/Remove Programs `DisplayIcon` |
| `installer-welcome.bmp` (164x314) | left image of the welcome and finish pages, installer and uninstaller (`MUI_WELCOMEFINISHPAGE_BITMAP`, `MUI_UNWELCOMEFINISHPAGE_BITMAP`) |
| `installer-header.bmp` (150x57) | header image of the inner pages (`MUI_HEADERIMAGE`, right-aligned) |
| `installer-small.bmp` (55x58) | `installer.iss` only (`WizardSmallImageFile`) |

The driver DLL carries the same icon (`src/platform/win/trinoodbc.ico`, resource `IDI_TRINOODBC`
= 1): Explorer shows it for `trinoodbc.dll`, and the DSN dialog uses it as its window icon and next
to the trademark line at the bottom. After changing the SVG, run `make_icons.sh` and copy
`generated/trinoodbc.ico` over `src/platform/win/trinoodbc.ico`.

Trino and the Trino logo are trademarks of the Trino Software Foundation. This driver is an
independent project and is not affiliated with or endorsed by the Trino Software Foundation. The
welcome page, the `LegalTrademarks` version resource of the setup and of `trinoodbc.dll`, and the
DSN dialog say so.

## What the installer does

NSIS only ships 32-bit installer stubs, so the installer itself is a 32-bit Unicode program. It
refuses to run on 32-bit Windows. It uses `SetRegView 64` and `$PROGRAMFILES64`, so it writes the
native 64-bit registry view and `C:\Program Files`. 64-bit applications and the 64-bit ODBC
Administrator read those. It needs administrator rights (`RequestExecutionLevel admin`, checked
again at startup) and Windows 10 1903 (build 18362) or later, the same minimum as `installer.iss`.
On Windows on ARM it warns that only x64 applications running under emulation can load the x64
driver, and continues if you agree. Only one setup can run at a time: it uses the same mutex as the
Inno Setup installer.

Pages: welcome, license (only when a license file was found at build time), components, directory
(default `C:\Program Files\TrinoODBC`; an upgrade reuses the folder of the installed version),
progress, finish. The finish page can open the 64-bit ODBC Data Source Administrator and the quick
start file. It also says that the DSN dialog pre-fills the time zone `Europe/Istanbul` (UTC+3,
Türkiye / Istanbul), stored as the `TimeZone` key, and that another IANA zone or `system` (the
Windows zone) can be chosen there.

### Components

| Component | Default | Installs |
|---|---|---|
| Driver (required) | on | `trinoodbc.dll` (+ staged dependency DLLs), `trinoodbc.ico`, `VERSION.txt`, `register_driver.ps1`, `LICENSE.txt` (if any), `ODBC-DSN-QUICKSTART.txt`, `uninstall.exe`; the ODBC registration |
| Documentation | on | `docs\*.md` |
| Power BI custom connector | on | `powerbi\TrinoODBC.mez` and `powerbi\README.md`, plus a copy in `Documents\Power BI Desktop\Custom Connectors\` (folder created) |

The ODBC registration is exactly what `register_driver.ps1` and `installer.iss` write:

| Key (HKLM, 64-bit view) | Value | Data |
|---|---|---|
| `SOFTWARE\ODBC\ODBCINST.INI\ODBC Drivers` | `Trino ODBC Driver` | `Installed` |
| `SOFTWARE\ODBC\ODBCINST.INI\Trino ODBC Driver` | `Driver`, `Setup` | `<install dir>\trinoodbc.dll` |
| | `Description` | `Trino ODBC Driver (ODBC 3.8, Unicode)` |
| | `APILevel` / `ConnectFunctions` / `DriverODBCVer` / `FileUsage` / `SQLLevel` | `2` / `YYN` / `03.80` / `0` / `1` (REG_SZ) |
| | `UsageCount` | `1` (REG_DWORD) |

Add/Remove Programs (`HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\TrinoODBC`):
`DisplayName` = `Trino ODBC Driver (x64)`, `DisplayVersion`, `Publisher` =
`Trino ODBC (open source)`, `UninstallString`, `QuietUninstallString`, `InstallLocation`,
`DisplayIcon` = `<install dir>\trinoodbc.ico` (the Trino logo), `EstimatedSize`, `NoModify` = 1, `NoRepair` = 1. When the Power BI connector was
copied, `PowerBIConnector` records where it went.

`ODBC-DSN-QUICKSTART.txt` (UTF-16 with BOM) explains how to create a DSN, in the 64-bit
`odbcad32.exe` or with `Add-OdbcDsn`. It lists the keys for a TLS + LDAP connection (`Host`,
`Port`, `SSL=1`, `SSLVerification=Full`, `UseSystemTrustStore=1` or `TrustedCerts=<pem>`,
`AuthenticationType=LDAP`, `UID`, `PWD`, `Catalog`, `Schema`, `TimeZone`), explains the time zone
default (`Europe/Istanbul`, UTC+3; `TimeZone=system` for the Windows zone) and gives a DSN-less
connection string. [docs/CONNECTION-OPTIONS.md](../../docs/CONNECTION-OPTIONS.md) describes every key.

**Power BI connector location.** Power BI Desktop loads connectors from the Documents folder of the
user who runs it. The installer copies the `.mez` into the Documents folder of the account that
runs setup. That is the logged-on user when an administrator elevates their own session. It is the
other account when a standard user enters an administrator's credentials. In that case, and for
other Power BI users on the machine, copy `C:\Program Files\TrinoODBC\powerbi\TrinoODBC.mez` into
their `Documents\Power BI Desktop\Custom Connectors\` yourself. Deployments that run as SYSTEM
(Intune, SCCM) or another service account skip the per-user copy. Power BI Desktop also has to
allow uncertified connectors: *Options > Security > Data Extensions*, see
[powerbi/README.md](../../powerbi/README.md). An on-premises data gateway needs the `.mez` in its
own configured connectors folder.

### Command line and silent install

```bat
TrinoODBC-1.0.0-windows-x64-setup.exe /S
TrinoODBC-1.0.0-windows-x64-setup.exe /S /NOPOWERBI /NODOCS /D=D:\Drivers\TrinoODBC
"C:\Program Files\TrinoODBC\uninstall.exe" /S
```

* `/S` installs silently with the default components. Every message box has a silent default, and
  messages that would stop the installation make it exit instead.
* `/NODOCS` and `/NOPOWERBI` deselect those components (in silent mode too).
* `/D=<dir>` sets the install folder. It must be the last argument and must not be quoted, even
  when it contains spaces. Folders under `%WINDIR%` are refused.
* Exit codes: `0` success, `1` cancelled, `2` aborted (unsupported Windows, no administrator
  rights, another setup running, write error), `3010` success in silent mode but a restart is
  needed.

### Upgrades and files in use

Running a newer installer over an installed version replaces the files in the same folder and
rewrites the registration. It first removes the old `docs\*.md`, so docs that were renamed or
dropped do not linger. Applications that still have the driver loaded (ODBC Administrator, Power
BI, Excel) do not block the upgrade. The loaded `trinoodbc.dll` is renamed to `trinoodbc.dll.old`,
and Windows deletes it at the next restart. The new DLL is in place at once, and new connections
use it. Only if even that rename fails is the new file queued to replace the old one at the next
restart. In that case the finish page asks for a restart, or the exit code is 3010 in silent mode.
DSNs are never touched.

If the Inno Setup build of the driver is installed, the installer warns first. Both installers
register the same driver name, and uninstalling either one removes that registration.

### Uninstaller

Settings > Apps, or `uninstall.exe [/S]`, removes:

* the files it installed (known names only). Folders are deleted only when they are empty, so files
  you added yourself stay. DLLs that are still loaded are deleted at the next restart,
* both ODBC registry entries (the `Trino ODBC Driver` key and the `ODBC Drivers` value). They are
  removed only when the registered `Driver` path is this installation's `trinoodbc.dll`. A
  registration that `register_driver.ps1` pointed at another copy is kept, and the uninstaller says
  so in its log,
* the Add/Remove Programs entry,
* the Power BI connector: the copy recorded at install time and the one in the Documents folder of
  the user who runs the uninstaller. `Custom Connectors` and `Power BI Desktop` are removed too if
  they end up empty.

User and system DSNs are kept, but they stop working until the driver is installed again. The
confirmation page says so.

## Checking it on Windows

The 1.0.0 installer has been installed and used on Windows x64 (registration, DSN, connection,
queries, Power BI Desktop). The upgrade-in-place, silent-install and uninstall steps below have
not been recorded separately, so run the full list after any change to the script, on a Windows
10 1903+ / 11 x64 machine (a throw-away VM is best):

1. Run the installer, keeping all components selected. Then check the registration in an elevated
   `cmd.exe`:
   `reg query "HKLM\SOFTWARE\ODBC\ODBCINST.INI\Trino ODBC Driver"` and
   `reg query "HKLM\SOFTWARE\ODBC\ODBCINST.INI\ODBC Drivers" /v "Trino ODBC Driver"`.
   Nothing should appear under `HKLM\SOFTWARE\WOW6432Node\ODBC\ODBCINST.INI`.
2. In `C:\Windows\System32\odbcad32.exe`, open *Drivers*. It should list *Trino ODBC Driver* with
   the version from the DLL. *Add* should open the driver's DSN dialog with the Trino logo in its
   title bar and *Time zone* pre-filled with `Europe/Istanbul`; after *OK*,
   `reg query "HKLM\SOFTWARE\ODBC\ODBC.INI\<name>" /v TimeZone` (system DSN) shows it. The setup
   `.exe`, the Add/Remove Programs entry and the wizard pages should show the Trino logo.
3. `Documents\Power BI Desktop\Custom Connectors\TrinoODBC.mez` should exist, and
   `ODBC-DSN-QUICKSTART.txt` should open in Notepad.
4. Test an upgrade while the ODBC Administrator has the driver loaded: `trinoodbc.dll.old`
   appears and there is no restart prompt.
5. Uninstall. The files, both registry entries, the Add/Remove Programs entry and the `.mez`
   should all be gone.
6. Repeat 1 and 5 silently: `setup.exe /S`, then `echo %ERRORLEVEL%`, then `uninstall.exe /S`.

The installer and the uninstaller are not code-signed, so SmartScreen warns about an "unknown
publisher". To sign from macOS or Linux, use `osslsigncode` (`brew install osslsigncode`):

```sh
osslsigncode sign -pkcs12 codesign.pfx -readpass pass.txt -n "Trino ODBC Driver" \
    -t http://timestamp.digicert.com -in TrinoODBC-1.0.0-windows-x64-setup.exe -out signed.exe
```

The uninstaller is generated inside the installer, so it stays unsigned unless the script signs
it at compile time with NSIS's `!uninstfinalize`. The script does not do that yet.

## Differences from installer.iss

| | `installer.nsi` (this) | `installer.iss` |
|---|---|---|
| Built on | macOS / Linux / Windows (`makensis`) | Windows (`ISCC.exe`) |
| Driver build | mingw-w64 cross build, static dependencies | MSVC + vcpkg DLLs |
| Architectures | x64 | x64, x86, arm64 |
| VC++ runtime | not needed (UCRT is part of Windows 10) | runs a bundled `vc_redist` when present |
| Components | driver, docs, Power BI connector | driver and docs, no component page |
| Add/Remove Programs key | `TrinoODBC` | `{7E1C2D8A-5B3F-4C2E-9A1D-6F0B2C3D4E5F}_is1` |
| Branding | `-DASSETS` (default `packaging/assets/generated` via `build_installer.sh`) | `/DAssetsDir` (default `..\assets\generated`): `SetupIconFile`, `WizardImageFile`, `WizardSmallImageFile`, `UninstallDisplayIcon={app}\trinoodbc.ico` |
